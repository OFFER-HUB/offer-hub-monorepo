## Overview

The Orders API covers the full order lifecycle: creating an order, reserving funds, setting up escrow, tracking milestones, completing delivery, and attaching notes or files. Every endpoint requires a valid JWT (user session token) in the `Authorization` header.

For background on order states and transitions, see [State Machines](/docs/guide/state-machines). For the escrow prepare-sign-submit flow, see [Escrow Flows](/docs/guide/escrow-flows). For the milestone transition guard, see the [Milestone state machine](/docs/guide/state-machines#milestone).

## Endpoints

### POST /orders

Create a new order.

| Property        | Value |
|-----------------|-------|
| **Auth**        | JWT (Bearer) |
| **Idempotency** | `Idempotency-Key` header **required** |

Send `Idempotency-Key` with every create request. The server returns the same response for duplicate requests that share a key, so retrying a failed network call will not create a duplicate order.

**Request body**

```json
{
  "offerId": "off_...",
  "buyerId": "usr_...",
  "sellerId": "usr_...",
  "amount": "150.00",
  "currency": "USDC",
  "milestones": [
    { "ref": "milestone-1", "title": "First draft", "amount": "75.00" },
    { "ref": "milestone-2", "title": "Final delivery", "amount": "75.00" }
  ]
}
```

**Response** `201 Created`

```json
{
  "success": true,
  "data": {
    "id": "ord_...",
    "status": "ORDER_CREATED",
    ...
  }
}
```

### GET /orders

List all orders visible to the authenticated user (as buyer or seller).

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

**Query parameters**

| Parameter | Type   | Description |
|-----------|--------|-------------|
| `status`  | string | Filter by order status (e.g. `IN_PROGRESS`) |
| `page`    | number | Page number (default: 1) |
| `limit`   | number | Results per page (default: 20) |

**Response** `200 OK`

```json
{
  "success": true,
  "data": [ /* array of order objects */ ],
  "meta": { "page": 1, "limit": 20, "total": 42 }
}
```

### POST /orders/:id/cancel

Cancel an order. **Only allowed when the order is in `ORDER_CREATED` or `FUNDS_RESERVED` status.** The order moves to `CLOSED`.

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

<Callout type="warning">
  Cancellation is not available after escrow has been initiated. Attempting to cancel an order in any status other than `ORDER_CREATED` or `FUNDS_RESERVED` returns `409 Conflict`. There is no `CANCELLED` status â€” cancelled orders move to `CLOSED`.
</Callout>

**Response** `200 OK`

```json
{
  "success": true,
  "data": { "id": "ord_...", "status": "CLOSED" }
}
```

### POST /orders/:id/escrow/submit

Submit a signed escrow transaction. Used for both create-escrow and fund-escrow flows.

| Property        | Value |
|-----------------|-------|
| **Auth**        | JWT (Bearer) |
| **Idempotency** | `Idempotency-Key` header **required** |

**Request body**

```json
{
  "signedXdr": "AAAAAgAAAA...",
  "type": "CREATE_ESCROW"
}
```

`type` must match the transaction prepared in the corresponding prepare step (`CREATE_ESCROW` or `FUND_ESCROW`).

**Response** `200 OK`

```json
{
  "success": true,
  "data": {
    "id": "ord_...",
    "status": "ESCROW_CREATING"
  }
}
```

## Order status reference

| Status             | Description |
|--------------------|-------------|
| `ORDER_CREATED`    | Order created, awaiting fund reservation. |
| `FUNDS_RESERVED`   | Funds reserved by the buyer. |
| `ESCROW_CREATING`  | Create-escrow transaction submitted; awaiting confirmation. |
| `ESCROW_FUNDING`   | Fund-escrow transaction submitted; awaiting confirmation. |
| `ESCROW_FUNDED`    | Escrow contract is live and funded. |
| `IN_PROGRESS`      | Work has begun. |
| `DELIVERED`        | Seller has marked work as delivered. |
| `RELEASE_REQUESTED`| Buyer has requested escrow release. |
| `RELEASED`         | Funds released to seller. |
| `REFUND_REQUESTED` | Refund has been requested. |
| `REFUNDED`         | Funds returned to buyer. |
| `DISPUTED`         | A dispute has been opened. |
| `CLOSED`           | Order is closed (includes cancelled orders). |
