Two endpoints need no credential and exist for clients and load balancers. `GET /config` lives in `ConfigController` (`apps/api/src/modules/config/config.controller.ts`). The basic health route lives in `HealthController` (`apps/api/src/modules/health/health.controller.ts`) and `HealthService` (`health.service.ts`). With the global `/api/v1` prefix from `apps/api/src/main.ts`, the paths below are the full routes.

| Method | Path | Scope | Success status | Controller handler |
| --- | --- | --- | --- | --- |
| <Badge variant="success">GET</Badge> | `/api/v1/config` | none (public) | `200 OK` | `ConfigController.getConfig` |
| <Badge variant="success">GET</Badge> | `/api/v1/health` | none (public) | `200 OK` | `HealthController.getHealth` |

<Callout type="note">
  The TypeScript SDK (`packages/sdk`) has no resource for these routes, so the TypeScript examples use plain `fetch`. Both handlers are marked `@Public()`, which makes `ApiKeyGuard` skip them, so no `Authorization` header is needed.
</Callout>

## Common behavior

- **No scope and no request body.** Neither of these routes reads a body or declares `@Scopes`.
- **No idempotency.** Both are `GET` routes; the global idempotency guard only acts on `POST`, `PUT` and `PATCH`.
- **Rate limiting still applies.** The global `RateLimitGuard` allows 100 requests per 60 seconds, counted per IP for requests without a key. Poll health sparingly; a load balancer probe every 10 seconds is well within the limit.
- **Envelope differs per route.** `ResponseInterceptor` leaves a single-key `{ data: ... }` payload untouched and wraps everything else in `{ data, meta }`. So `GET /config` returns `{ "data": { ... } }` with **no `meta`**, while `GET /health` is wrapped as `{ "data": { ... }, "meta": { "requestId", "timestamp" } }`.
- **Errors** use `{ "error": { "code", "message" } }`. The only error these routes can realistically return is `429 RATE_LIMITED`; see [Error Codes](/docs/api-reference/errors).

## GET /api/v1/config

Returns platform configuration for clients that want to inspect active features, supported currencies, and configured provider integrations.

<Callout type="warning">
  **The limits and provider names in the controller reflect platform defaults.** Treat this response as documentation of system capability, and confirm real limits on the specific endpoint you call.
</Callout>

What is fixed and what is computed:

| Field | How it is produced |
| --- | --- |
| `currencies` | Supported currencies: `["USD", "USDC"]` |
| `limits.order` | Min `1.00`, max `50000.00` |
| `limits.payout` | Minimum bank-account quote is `5.00` USD |
| `features.milestones`, `features.disputes` | `true` |
| `features.sse` | `true` (`GET /events` domain event stream) |
| `features.blindpay`, `features.trustlessWork` | `true` when provider integrations are enabled |
| `providers.fiat`, `providers.escrow` | `"blindpay"` and `"trustless_work"` |
| `network` | `"mainnet"` for live deployment, `"testnet"` for sandbox |
| `version` | `npm_package_version` when available, otherwise `"1.0.0"` |

## GET /api/v1/health

The basic check. It answers immediately without blocking I/O, confirming the API process is alive and accepting traffic. Use it for load balancer and container orchestrator health checks.

<ResponseSchema
  label="Basic health response (200 OK)"
  fields={[
    { name: "data.status", type: "string", required: true, description: "Service status (ok).", enum: ["ok"] },
    { name: "data.timestamp", type: "string", required: true, description: "ISO 8601 time of the check." },
    { name: "meta", type: "object", required: true, description: "requestId (when sent) and timestamp." }
  ]}
  example={{
    data: { status: "ok", timestamp: "2026-02-18T10:00:00.000Z" },

  }}
/>

| Status | `error.code` | When |
| --- | --- | --- |
| `503` | `SERVICE_UNAVAILABLE` | Service is down or in maintenance |
