## Overview

The Resolution API handles the end-of-order escrow settlement flows: releasing funds to the seller, refunding the buyer, and opening a dispute. Each path follows a prepare→sign→submit pattern — the server returns an unsigned XDR transaction, the client signs it with their private key, and the signed transaction is submitted through the relevant submit endpoint.

Every endpoint requires a valid JWT (user session token) in the `Authorization` header.

<Callout type="info">
  All `/prepare` endpoints return an **unsigned XDR transaction**. You must sign this transaction client-side (using the Stellar SDK or a compatible wallet) before submitting it. The server never holds or uses your private key.
</Callout>

For sequence diagrams of each flow, see [Escrow Flows](/docs/guides/escrow-flows).

## Endpoints

### POST /orders/:orderId/resolution/release/prepare

Prepare an unsigned escrow-release transaction. Use this when the buyer approves the delivery and wants to release funds to the seller.

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

The order must be in `DELIVERED` or `RELEASE_REQUESTED` status for this endpoint to succeed.

**Response** `200 OK`

```json
{
  "success": true,
  "data": {
    "unsignedXdr": "AAAAAgAAAA...",
    "type": "RELEASE",
    "orderId": "ord_..."
  }
}
```

After receiving the XDR:

1. Sign it with the buyer's Stellar keypair.
2. Submit the signed XDR through the dispute resolution submit endpoint or directly to the Stellar network via Trustless Work, depending on your integration.

---

### POST /orders/:orderId/resolution/refund/prepare

Prepare an unsigned escrow-refund transaction. Use this when both parties agree to return funds to the buyer.

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

The order must be in `REFUND_REQUESTED` status.

**Response** `200 OK`

```json
{
  "success": true,
  "data": {
    "unsignedXdr": "AAAAAgAAAA...",
    "type": "REFUND",
    "orderId": "ord_..."
  }
}
```

---

### POST /orders/:orderId/resolution/dispute/prepare

Prepare an unsigned dispute transaction. This initiates the dispute flow on-chain, moving the order to `DISPUTED`.

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

Either the buyer or seller may open a dispute. The order must be in `ESCROW_FUNDED` or `IN_PROGRESS` or `DELIVERED` status.

**Response** `200 OK`

```json
{
  "success": true,
  "data": {
    "unsignedXdr": "AAAAAgAAAA...",
    "type": "DISPUTE",
    "orderId": "ord_..."
  }
}
```

---

### POST /orders/:orderId/resolution/dispute

Submit a dispute against an order. This endpoint combines the dispute reason and evidence with the signed XDR produced from the prepare step.

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

**Request body**

```json
{
  "signedXdr": "AAAAAgAAAA...",
  "reason": "NOT_DELIVERED",
  "description": "The seller has not delivered any files after 14 days."
}
```

| Field         | Type   | Required | Description |
|---------------|--------|----------|-------------|
| `signedXdr`   | string | Yes      | Signed XDR from the dispute prepare step. |
| `reason`      | string | Yes      | One of `NOT_DELIVERED`, `QUALITY_ISSUE`, `OTHER`. |
| `description` | string | No       | Free-text explanation of the dispute. |

**Response** `201 Created`

```json
{
  "success": true,
  "data": {
    "disputeId": "dsp_...",
    "orderId": "ord_...",
    "status": "OPEN",
    "reason": "NOT_DELIVERED",
    "createdAt": "2026-11-21T09:00:00.000Z"
  }
}
```

The order status moves to `DISPUTED` after a successful submission.

## Resolution flow summary

| Goal              | Step 1 — Prepare                                   | Step 2 — Sign        | Step 3 — Submit |
|-------------------|----------------------------------------------------|----------------------|-----------------|
| Release to seller | `POST …/resolution/release/prepare`                | Sign XDR client-side | Submit to Stellar / Trustless Work |
| Refund to buyer   | `POST …/resolution/refund/prepare`                 | Sign XDR client-side | Submit to Stellar / Trustless Work |
| Open dispute      | `POST …/resolution/dispute/prepare`                | Sign XDR client-side | `POST …/resolution/dispute` |

## Order status transitions

| Action           | Required status(es)                              | Resulting status   |
|------------------|--------------------------------------------------|--------------------|
| Release prepare  | `DELIVERED`, `RELEASE_REQUESTED`                 | — (no change yet)  |
| Refund prepare   | `REFUND_REQUESTED`                               | — (no change yet)  |
| Dispute prepare  | `ESCROW_FUNDED`, `IN_PROGRESS`, `DELIVERED`      | — (no change yet)  |
| Dispute submit   | `ESCROW_FUNDED`, `IN_PROGRESS`, `DELIVERED`      | `DISPUTED`         |
