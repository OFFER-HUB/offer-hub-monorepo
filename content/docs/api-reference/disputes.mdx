## Overview

The Disputes API exposes endpoints for buyers and sellers to view and cancel disputes they are party to. Opening a dispute happens through the [Resolution API](/docs/api-reference/resolution) (`POST /orders/:orderId/resolution/dispute`).

Every endpoint requires a valid JWT (user session token) in the `Authorization` header.

For the dispute status transitions and the guard on `POST /disputes/{id}/assign` and `POST /disputes/{id}/resolve`, see the [Dispute state machine](/docs/guide/state-machines#dispute).

<Callout type="note">
  Admin resolution endpoints (reviewing evidence, applying outcomes) are not documented here and are not available to participants.
</Callout>

---

## Endpoints

### GET /disputes

List all disputes where the authenticated user is the buyer or seller.

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

**Query parameters**

| Parameter | Type   | Description |
|-----------|--------|-------------|
| `status`  | string | Filter by dispute status: `OPEN`, `UNDER_REVIEW`, or `RESOLVED`. |
| `page`    | number | Page number (default: 1). |
| `limit`   | number | Results per page (default: 20). |

**Response** `200 OK`

```json
{
  "success": true,
  "data": [
    {
      "id": "dsp_...",
      "orderId": "ord_...",
      "status": "OPEN",
      "reason": "NOT_DELIVERED",
      "openedBy": "BUYER",
      "createdAt": "2026-11-21T09:00:00.000Z"
    }
  ],
  "meta": { "page": 1, "limit": 20, "total": 3 }
}
```

---

### GET /disputes/:id

Fetch a single dispute by ID. Returns `403 Forbidden` if the authenticated user is not a participant.

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

**Response** `200 OK`

```json
{
  "success": true,
  "data": {
    "id": "dsp_...",
    "orderId": "ord_...",
    "status": "UNDER_REVIEW",
    "reason": "QUALITY_ISSUE",
    "description": "Deliverables did not match the agreed specification.",
    "openedBy": "BUYER",
    "outcome": null,
    "createdAt": "2026-11-21T09:00:00.000Z",
    "updatedAt": "2026-11-21T10:30:00.000Z"
  }
}
```

`outcome` is `null` until the dispute is resolved.

---

### POST /disputes/:id/cancel

Cancel an open dispute. Only the participant who opened the dispute may cancel it, and only while the status is `OPEN`.

| Property | Value |
|----------|-------|
| **Auth** | JWT (Bearer) |

**Response** `200 OK`

```json
{
  "success": true,
  "data": {
    "id": "dsp_...",
    "status": "RESOLVED",
    "outcome": null,
    "cancelledAt": "2026-11-21T11:00:00.000Z"
  }
}
```

## Reference tables

### Dispute reasons

| Reason           | Description |
|------------------|-------------|
| `NOT_DELIVERED`  | The seller did not deliver the agreed work. |
| `QUALITY_ISSUE`  | Work was delivered but does not meet the agreed standard. |
| `OTHER`          | Any other reason not covered above. |

### Who can open a dispute

| Role     | Can open dispute |
|----------|-----------------|
| `BUYER`  | Yes |
| `SELLER` | Yes |

### Dispute statuses

| Status         | Description |
|----------------|-------------|
| `OPEN`         | Dispute submitted; under initial review. |
| `UNDER_REVIEW` | Evidence is being assessed. |
| `RESOLVED`     | Dispute closed with an outcome applied. |

### Dispute outcomes

| Outcome        | Description |
|----------------|-------------|
| `FULL_RELEASE` | Full escrow amount released to the seller. |
| `FULL_REFUND`  | Full escrow amount refunded to the buyer. |
| `SPLIT`        | Escrow amount split between buyer and seller. |
