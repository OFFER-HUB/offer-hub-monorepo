## Option 1: Installer

`create-offer-hub-orchestrator` is an interactive setup wizard. It writes your `.env`, applies database migrations and bootstraps the platform records a fresh instance needs.

### Step 1 — Clone the starter shell

```bash
git clone https://github.com/OFFER-HUB/OFFER-HUB.git
cd OFFER-HUB
npm install
```

### Step 2 — Run the installer

<CommandLine>npx create-offer-hub-orchestrator</CommandLine>

The wizard prompts for:

| Prompt | What to enter |
|---|---|
| API port | `4000` unless you need another port |
| PostgreSQL URL | Your database connection string |
| Redis URL | `redis://` or `rediss://` for TLS |
| Stellar network | `testnet` to start, `mainnet` when you are ready |
| Stellar RPC URL | Your Stellar RPC endpoint |
| Trustless Work API key | From your Trustless Work dashboard |
| Trustless Work webhook secret | From your Trustless Work dashboard |
| Public URL | The HTTPS URL your instance will serve |

The wizard then generates `OFFERHUB_MASTER_KEY` and writes it into `.env`, applies migrations, and creates the platform records.

<Callout type="warning">
  **Back up `OFFERHUB_MASTER_KEY`.** It is the only credential that can create the first API key on the instance. Store it in a secrets manager, not in chat or a ticket.
</Callout>

### Step 3 — Start the API

<CommandLine>npm run dev</CommandLine>

The API listens on `http://localhost:4000` by default.

### Step 4 — Verify

<CommandLine>curl http://localhost:4000/api/v1/health</CommandLine>

```json
{
  "status": "healthy",
  "services": {
    "database": "connected",
    "redis": "connected"
  }
}
```

## Option 2: Manual setup

Use this path when you need full control over the infrastructure.

### Prerequisites

- **Node.js** 20 or later
- **npm** 10 or later
- **PostgreSQL** 14 or later
- **Redis** 6 or later
- A **Trustless Work** API key for escrow
- A **BlindPay** account if you want the off-ramp corridors

### Step 1 — Clone the starter shell

```bash
git clone https://github.com/OFFER-HUB/OFFER-HUB.git
cd OFFER-HUB
```

### Step 2 — Install dependencies

<CommandLine>npm install</CommandLine>

### Step 3 — Start infrastructure

With Docker Compose, from the repository root:

<CommandLine>docker compose up -d</CommandLine>

This starts PostgreSQL on `5432` and Redis on `6379`.

### Step 4 — Configure the environment

```bash
cp .env.example .env
```

Minimum variables for a local instance:

```env
# Server
NODE_ENV=development
PORT=4000

# Database and queue
DATABASE_URL=postgresql://user:password@localhost:5432/database
REDIS_URL=redis://localhost:6379

# Operator credential
OFFERHUB_MASTER_KEY=your-master-key

# Escrow provider
TRUSTLESS_API_KEY=your-trustless-api-key
TRUSTLESS_WEBHOOK_SECRET=your-trustless-webhook-secret

# Stellar
STELLAR_NETWORK=testnet
STELLAR_RPC_URL=https://your-stellar-rpc-endpoint
STELLAR_USDC_ASSET_CODE=USDC
STELLAR_USDC_ISSUER=your-usdc-issuer

# Public URL used for callbacks
PUBLIC_BASE_URL=http://localhost:4000
```

The full variable reference is on the [Configuration](/docs/configuration) page.

### Step 5 — Apply migrations

<CommandLine>npm run prisma:generate && npx prisma migrate deploy</CommandLine>

### Step 6 — Start the API

<CommandLine>npm run dev</CommandLine>

### Step 7 — Verify

<CommandLine>curl http://localhost:4000/api/v1/health</CommandLine>

## Option 3: SDK only

If an Orchestrator instance already exists, install the client and point it at that instance:

<CommandLine>npm install @offerhub/sdk</CommandLine>

```typescript
import { OfferHubSDK } from "@offerhub/sdk";

const sdk = new OfferHubSDK({
  apiUrl: "https://your-orchestrator.example.com",
  apiKey: process.env.OFFERHUB_API_KEY!,
});

const user = await sdk.users.create({
  externalUserId: "your-user-123",
  email: "buyer@example.com",
  type: "BUYER",
});
```

<Callout type="danger">
  The SDK is server-side only. An API key in browser code is a leaked key. To act on behalf of a signed-in user in a browser, use a one-hour token and `sdk.asUser(token)`.
</Callout>

See the [SDK Quick Start](/docs/sdk/quick-start) for the full resource list.

## Creating your first API key

Every request to the Orchestrator is authenticated. The first key is created with the operator master key.

### Step 1 — Create a support-scoped key

Use the master key **once**, to create an operator key with `support` scope:

```bash
curl -X POST http://localhost:4000/api/v1/auth/api-keys \
  -H "Authorization: Bearer your-master-key" \
  -H "Content-Type: application/json" \
  -d '{"name": "Operator", "scopes": ["support"]}'
```

```json
{
  "data": {
    "id": "key_...",
    "key": "ohk_live_...",
    "name": "Operator",
    "scopes": ["support"]
  }
}
```

<Callout type="danger">
  The `key` value is shown once. Store it in your secrets manager immediately.
</Callout>

### Step 2 — Create scoped keys for your backend

With the support key, create the keys your marketplace actually uses:

```bash
# Read-only key for dashboards and reporting
curl -X POST http://localhost:4000/api/v1/auth/api-keys \
  -H "Authorization: Bearer ohk_live_your_support_key" \
  -H "Content-Type: application/json" \
  -d '{"name": "Marketplace read", "scopes": ["read"]}'

# Read/write key for order and payout endpoints
curl -X POST http://localhost:4000/api/v1/auth/api-keys \
  -H "Authorization: Bearer ohk_live_your_support_key" \
  -H "Content-Type: application/json" \
  -d '{"name": "Marketplace backend", "scopes": ["read", "write"]}'
```

| Scope | Grants |
|---|---|
| `read` | Read endpoints |
| `write` | Create and update orders, escrows and payouts |
| `support` | Dispute resolution and support operations |

Keep `support` off the key your web request handlers use. Give it only to the service or operator that resolves disputes.

### Step 3 — Exchange a key for a short-lived token

Browser code should never see an API key. Exchange a key for a one-hour token on your server:

```bash
curl -X POST http://localhost:4000/api/v1/auth/api-keys/key_your_key_id/token \
  -H "Authorization: Bearer ohk_live_your_api_key"
```

The response contains an `ohk_tok_...` token valid for one hour. The CLI exposes the same operation as `offerhub keys token`.

## Troubleshooting the install

### Database connection failed

```bash
docker compose ps
docker compose up -d
```

### Migration errors

Confirm `DATABASE_URL` points at the database you expect, then:

<CommandLine>npx prisma migrate status</CommandLine>

<Callout type="warning">
  `prisma migrate reset` deletes all data. Use it in development only.
</Callout>

### Port already in use

Change `PORT` in `.env`, or stop the process using `4000`.

### API starts but returns 502 from Stellar

Check `STELLAR_NETWORK` and `STELLAR_RPC_URL`. A testnet URL paired with a mainnet network setting fails on every on-chain call.
