The `sdk.wallet` resource is used with a signed-in user session created by `sdk.asUser(token)`. Wallet operations require a 7-day JWT, not a marketplace API key.

<Callout type="note">
`@offerhub/sdk` 3.0.0 is in maintainer publishing. Until the package is live on npm, ask in the issue for a signature before relying on an SDK method or parameter that is not listed in this document.
</Callout>

## Create a user-session SDK

```typescript
import { OfferHubSDK } from '@offerhub/sdk';

const sdk = new OfferHubSDK({
  apiUrl: process.env.OFFERHUB_API_URL!,
  apiKey: process.env.OFFERHUB_API_KEY!,
});

const userSdk = sdk.asUser(userSessionJwt);
```

The API key initializes the marketplace SDK. `sdk.asUser(...)` binds the user-session JWT to wallet and other user resources.

## Supported wallet integrations

Use Stellar Wallets Kit in the marketplace frontend to connect:

- Freighter (now branded Varial)
- Lobstr
- xBull

The Orchestrator never stores a private key for an externally owned wallet.

## Wallet sign-in

Use the auth resource for wallet challenge/verify flows:

```typescript
const challenge = await sdk.auth.walletChallenge({ /* SDK-confirmed fields */ });

// Pass the challenge message to Stellar Wallets Kit and sign it in the user's wallet.
const signature = await walletSign(challenge.message);

const result = await sdk.auth.walletVerify({
  /* SDK-confirmed challenge and signature fields */
});

const userSdk = sdk.asUser(result.sessionJwt);
```

`walletChallenge` is public and returns a message for the user to sign. `walletVerify` is public and returns the user-session JWT. The resulting JWT is valid for 7 days.

```mermaid
sequenceDiagram
    participant App as Marketplace app
    participant Kit as Stellar Wallets Kit
    participant Wallet as User wallet
    participant Auth as OFFER-HUB auth

    App->>Auth: walletChallenge
    Auth-->>App: Challenge message
    App->>Kit: Open signing request
    Kit->>Wallet: Request signature
    Wallet-->>Kit: Signed message
    Kit-->>App: Signature
    App->>Auth: walletVerify
    Auth-->>App: 7-day JWT
```

## Prepare, sign, submit

A user-initiated operation returns unsigned transaction XDR. The marketplace sends that XDR to Stellar Wallets Kit; the user approves and signs it; the signed XDR is submitted to the Orchestrator.

```mermaid
flowchart LR
    A[User action] --> B[Orchestrator prepares unsigned XDR]
    B --> C[Marketplace passes XDR to Stellar Wallets Kit]
    C --> D[User signs in Freighter/Varial, Lobstr, or xBull]
    D --> E[Marketplace receives signed XDR]
    E --> F[Submit signed XDR]
    F --> G[Stellar network]
```

The server never signs for an external user. Only the platform signer signs platform-authorized operations with the platform key.

## Wallet types

| Type | Description |
|---|---|
| `EXTERNAL` | User-owned wallet connected to the account; mainnet uses this type only |
| `INVISIBLE` | Testnet sandbox custody type only; not available as a mainnet wallet model |

## Testnet sandbox claim

`POST /api/v1/wallet/claim` and invisible wallets apply only to testnet sandbox deployments. The claim flow has a 90-day window. Mainnet does not expose a claim flow and uses user-owned wallets only.
