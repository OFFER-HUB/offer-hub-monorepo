> **Version notice:** These types reflect `@offerhub/sdk` **3.0.0**. If your installed version differs, check the changelog.

Disputes are opened through the [resolution endpoint](/docs/sdk/orders#open-a-dispute) on an order. The methods on `disputes` let you list, inspect, and cancel existing disputes.

---

## Methods

### List disputes

```ts
const disputes = await sdk.asUser(token).disputes.list();
```

Returns all disputes associated with the authenticated user, across all their orders.

**Returns:** `Dispute[]`

---

### Get a dispute

```ts
const dispute = await sdk.asUser(token).disputes.get(disputeId);
```

Fetches a single dispute by ID.

| Parameter | Type | Description |
|-----------|------|-------------|
| `disputeId` | `string` | ID of the dispute |

**Returns:** `Dispute`

---

### Cancel a dispute

```ts
await sdk.asUser(token).disputes.cancel(disputeId);
```

Cancels an open dispute. Only the party who opened the dispute can cancel it, and only while its status is `OPEN`.

| Parameter | Type | Description |
|-----------|------|-------------|
| `disputeId` | `string` | ID of the dispute to cancel |

**Returns:** `Dispute`

## Reference tables

### Dispute reasons

| Value | Description |
|-------|-------------|
| `NOT_DELIVERED` | The seller did not deliver the agreed work or goods |
| `QUALITY_ISSUE` | The delivery did not meet the agreed quality standard |
| `OTHER` | Any other reason (provide details in `description`) |

---

### Opener roles

Either party in an order can open a dispute.

| Value | Description |
|-------|-------------|
| `BUYER` | The dispute was opened by the buyer |
| `SELLER` | The dispute was opened by the seller |

---

### Dispute statuses

| Status | Description |
|--------|-------------|
| `OPEN` | Dispute opened; awaiting response from the other party |
| `UNDER_REVIEW` | An admin has taken the dispute under review |
| `RESOLVED` | The dispute has been resolved with a recorded outcome |

---

### Dispute outcomes

Outcomes are set when a dispute moves to `RESOLVED`.

| Value | Description |
|-------|-------------|
| `FULL_RELEASE` | Escrow funds released in full to the seller |
| `FULL_REFUND` | Escrow funds refunded in full to the buyer |
| `SPLIT` | Escrow funds split between buyer and seller |

## Opening a dispute

Disputes are opened through `sdk.asUser(token).resolution.dispute()`, not through the `disputes` namespace. The flow requires a prepare step that returns an unsigned XDR transaction for client-side signing.

```ts
import { createSdk } from "@offerhub/sdk";

const sdk = createSdk({ baseUrl: "https://api.offerhub.io" });

async function openDispute(token: string, orderId: string) {
  const user = sdk.asUser(token);

  // Step 1: Get the unsigned XDR transaction
  const { xdr } = await user.resolution.disputePrepare(orderId);

  // Step 2: Sign the transaction client-side with the user's key
  const signedXdr = await signWithUserKey(xdr); // your signing logic

  // Step 3: Submit the dispute
  const dispute = await user.resolution.dispute(orderId, {
    reason: "NOT_DELIVERED",
    signedXdr,
    description: "The seller has not delivered anything after two weeks.",
  });

  console.log(dispute.id, dispute.status); // e.g. "disp_...", "OPEN"
  return dispute;
}
```

The `reason` field must be one of `NOT_DELIVERED`, `QUALITY_ISSUE`, or `OTHER`. After submission, the dispute status will be `OPEN` and the order status will transition to `DISPUTED`.
