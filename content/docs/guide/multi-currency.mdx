</Callout>

## Supported Assets

### Currently Supported

| Name | Symbol | Type | Status |
| :--- | :--- | :--- | :--- |
| USD Coin | USDC | Stablecoin | Available |

<Badge variant="primary">USDC</Badge> is the only settlement asset supported by the Orchestrator today. All balances, escrow contracts, and settlement amounts are denominated in USDC.

The crypto deposit provider accepts USDC via Stellar wallet transfers, and all on-chain escrow operations use USDC through the Trustless Work integration.

### Planned Assets

The following assets are planned for future releases:

| Name | Symbol | Type | Status |
| :--- | :--- | :--- | :--- |
| Euro Coin | EURC | Stablecoin | Planned |
| Stellar Lumens | XLM | Native Asset | Planned |
| Argentine Peso Token | ARST | Custom Stellar Token | Planned |

<Callout type="tip">
  If you need support for a specific asset not listed above, [open a discussion](https://github.com/OFFER-HUB/offer-hub-monorepo/issues) on the repository.
</Callout>

## Automatic Conversion at Settlement (Planned)

<Callout type="warning">
  This feature is not yet implemented. The details below describe the planned design.
</Callout>

A future release will allow automatic conversion of assets during settlement via Stellar path payments. For example, a buyer could deposit XLM while the seller receives USDC, with the conversion happening atomically at settlement.

Path payments rely on the Stellar Decentralized Exchange (DEX) for liquidity. Sufficient liquidity between the asset pairs must exist to prevent excessive slippage.

## Configuration

The Orchestrator is configured for USDC settlement through environment variables:

```env
# Stellar network asset configuration
STELLAR_NETWORK=mainnet
STELLAR_USDC_ASSET_CODE=USDC
```

See the [Configuration](/docs/configuration) page for the full list of environment variables.

<Callout type="note">
  When additional assets are supported, they will be configurable through the same environment configuration. No changes to your integration code will be needed beyond updating environment variables.
</Callout>
