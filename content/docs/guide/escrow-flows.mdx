<Callout type="warning">
  The server never signs on behalf of the user. Every on-chain transaction must be signed client-side before submission.
</Callout>

## 1. Create Escrow

The client prepares, signs, and submits the escrow creation transaction.

```mermaid
sequenceDiagram
  participant Client
  participant API

  Client->>API: POST /orders/:id/escrow/prepare
  API-->>Client: { xdr: "<unsigned XDR>" }
  Note over Client: Sign XDR with Stellar Wallets Kit
  Client->>API: POST /orders/:id/escrow/submit { signedXdr }
  API-->>Client: { data: { status: "ESCROW_CREATING" } }
```

## 2. Fund Escrow

Once the contract is deployed, the buyer funds it with USDC.

```mermaid
sequenceDiagram
  participant Client
  participant API

  Client->>API: POST /orders/:id/escrow/fund/prepare
  API-->>Client: { xdr: "<unsigned XDR>" }
  Note over Client: Sign XDR with Stellar Wallets Kit
  Client->>API: POST /orders/:id/escrow/fund/submit { signedXdr }
  API-->>Client: { data: { status: "ESCROW_FUNDED" } }
```

## 3. Release Funds

The buyer approves delivery and releases funds to the seller.

## 5. Dispute

Either party opens a dispute. The prepare/sign flow stages the on-chain transaction; the final POST opens the dispute record.

```mermaid
sequenceDiagram
  participant Client
  participant API

  Client->>API: POST /orders/:orderId/resolution/dispute/prepare
  API-->>Client: { xdr: "<unsigned XDR>" }
  Note over Client: Sign XDR with Stellar Wallets Kit
  Client->>API: POST /orders/:orderId/resolution/dispute { signedXdr, reason }
  API-->>Client: { data: { status: "DISPUTED", disputeId: "dsp_<32chars>" } }
```
