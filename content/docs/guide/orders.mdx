## Overview

An order represents an agreement between a buyer and a seller for a service or deliverable. The OFFER-HUB Orchestrator manages the full order lifecycle: from initial creation and fund reservation through escrow setup, work delivery, and final settlement. All funds flow through non-custodial Trustless Work Soroban escrow contracts denominated in USDC.

## Order Lifecycle

Orders move through the following statuses in sequence:

1. **ORDER_CREATED** — The buyer submits the order. Funds have not moved yet.
2. **FUNDS_RESERVED** — The buyer's payment is reserved pending escrow creation.
3. **ESCROW_CREATING** — The Orchestrator begins creating the Soroban escrow contract.
4. **ESCROW_FUNDING** — The escrow contract is live on Stellar; USDC funding is in progress.
5. **ESCROW_FUNDED** — USDC is confirmed inside the escrow contract.
6. **IN_PROGRESS** — Work begins. The seller can now deliver.
7. **DELIVERED** — The seller marks the deliverable as complete.
8. **RELEASE_REQUESTED** — The buyer approves delivery and requests fund release.
9. **RELEASED** — The escrow release transaction is confirmed on-chain.
10. **CLOSED** — The order is fully settled. No further transitions are possible.

Two additional paths can branch off this main sequence:

- **Refund path** — Either party can request a refund from `FUNDS_RESERVED` or `IN_PROGRESS`, moving the order to `REFUND_REQUESTED` → `REFUNDED` → `CLOSED`.
- **Dispute path** — Either party can open a dispute from `IN_PROGRESS` or `DELIVERED`, moving the order to `DISPUTED`.

## Escrow Integration

Orders at `ESCROW_CREATING` and beyond are backed by a Trustless Work Soroban smart contract on Stellar. The Orchestrator prepares unsigned XDR transactions; the user signs them client-side using Stellar Wallets Kit and submits them back to the API. The server never holds private keys. See [Escrow Overview](/docs/guide/escrow) and [Escrow Flows](/docs/guide/escrow-flows) for the full sequence.

## Cancelling an Order

<Callout type="warning">
  Cancellation is only available when the order is in `ORDER_CREATED` or `FUNDS_RESERVED`. Calling `POST /orders/:id/cancel` moves the order to `CLOSED`. There is no `CANCELLED` status.
</Callout>

## SDK Quick Start

Install the SDK and create your first order:

```bash
npm install @offerhub/sdk@3.0.0
```

```ts
import { sdk } from '@offerhub/sdk'

const order = await sdk.asUser(token).orders.create({
  offerId: 'off_<32chars>',
  milestones: [
    { title: 'Initial delivery', amount: 500_00 },
  ],
})

console.log(order.data.id)   // ord_<32chars>
console.log(order.data.status) // ORDER_CREATED
```
